## 4) 你问的重点：`package-lock.json` 是怎么来的

- 不是手写，一般由 `npm` 自动生成和维护。
- 典型触发：
  1. `npm install`
  2. `npm install <pkg>` / `npm uninstall <pkg>`
  3. `npm update`
- 作用：锁定“精确依赖树”，保证不同机器安装结果一致。
- 工程实践：建议提交到 Git，避免“我这能跑你那不能跑”。

## 5) 前端当前应用的技术架构

## 5.1 技术栈

- 框架与语言：React 18 + TypeScript
- 构建与开发：Vite 5（`@vitejs/plugin-react`）
- 路由：`react-router-dom`（BrowserRouter + 路由守卫）
- 样式体系：历史主题 CSS（`public/assets/css/*`）+ `src/styles/*` + `utilities-compat.css`
- 姿态能力：TensorFlow.js + MoveNet + MediaPipe Tasks Vision
- 3D/可视化依赖：`three`（当前为能力预留/局部使用）
- 部署：Nginx 静态托管（容器化由 `Dockerfile` + `nginx.conf`）

## 5.2 分层架构（从上到下）

1. 路由与应用壳层
- `src/main.tsx`：应用挂载、Router 注入
- `src/App.tsx`：路由表、鉴权守卫、旧链接兼容重定向

2. 页面编排层（Page）
- `src/pages/*`：业务页面（Auth / Blog / Food / Pose / Admin）
- 负责页面状态编排、组件组合、用户交互流程

3. 组件层（Component）
- `src/components/*`、`src/components/ui/*`
- 提供布局、导航、表单、按钮等复用 UI

4. 领域逻辑层（Domain/Feature）
- Pose：`src/pages/poseTool/*` + `src/lib/pose/*`
- Food：`src/lib/food/*`
- Report：`src/lib/report/*`
- 负责业务规则、分析逻辑、报告结构生成

5. 基础设施层（Infra）
- `src/lib/api.ts`：HTTP 基础请求
- `src/lib/auth.ts`、`src/state/auth-context.tsx`：鉴权与会话状态
- `src/lib/media.ts`：媒体 URL 解析

6. 资源与样式层
- `public/*`：静态资源（图片/模型/字体/CSS）
- `src/styles*`：全局样式、设计 token、模块样式

## 5.3 运行链路（Runtime Flow）

1. 浏览器加载 `index.html`，先加载全局 CSS。
2. Vite 注入并执行 `src/main.tsx`。
3. `BrowserRouter` 启动，进入 `App.tsx` 路由分发。
4. 页面组件调用 `lib/api.ts` 访问后端 `/api/*`。
5. Pose 页面按需加载 `public/assets/models/movenet/*` 模型，进行前端实时分析。
6. 结果在页面层渲染，并可进入历史/报告流程。

## 5.4 关键依赖关系

- 路由依赖页面：`App.tsx -> src/pages/*`
- 页面依赖能力层：`pages -> lib/* + components/*`
- Pose 页面强依赖模型资源：`lib/pose/movenetPose.ts -> public/assets/models/*`
- 全站样式双通道：
  - 构建通道：`styles.css` + `src/styles/*`（PostCSS + autoprefixer）
  - 静态通道：`index.html` 直接引入 `public/assets/css/*`

## 5.5 当前架构特点与注意点

- 优点：业务分层已经形成，Pose/Food/Blog 功能边界清晰。
- 风险点：样式来源双轨并存（`utilities-compat.css` + 大量历史 CSS），后续重构需逐步统一。
- 风险点：`public` 静态资源体积较大，需做分阶段引用审计后再精简。
- 风险点：部分占位图路径（`/figma/*.png`）需补齐或替换，避免线上 404。
