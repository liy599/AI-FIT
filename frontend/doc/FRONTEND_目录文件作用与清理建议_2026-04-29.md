# frontend 目录文件作用与清理建议（2026-04-29）

- 目录：`E:\trae_project\AI-FIT\frontend`
- 目标：说明每个主要文件/文件夹的作用，并给出“必须保留 / 可条件删除 / 可直接删除”判断。
- 判定依据：代码引用关系（`src` import）、`index.html` 静态资源引用、构建链路（Vite/TS/Tailwind）。

## 1. 根目录文件与文件夹

| 路径 | 作用 | 是否必须 | 删除建议 |
|---|---|---|---|
| `src/` | 前端业务源码（路由、页面、组件、API、状态） | 必须 | 不可删 |
| `public/` | 静态资源（图片、模型、字体、CSS） | 必须（大部分） | 仅可按引用审计后删 |
| `package.json` | npm 脚本与依赖定义 | 必须 | 不可删 |
| `package-lock.json` | 依赖锁定，保证环境一致 | 建议必须 | 建议保留 |
| `index.html` | Vite 入口 HTML，加载全局 CSS 和 `src/main.tsx` | 必须 | 不可删 |
| `vite.config.ts` | Vite 构建配置（当前生效） | 必须 | 不可删 |
| `tsconfig.json` | TS 编译配置（应用） | 必须 | 不可删 |
| `tsconfig.node.json` | TS 编译配置（Node/Vite） | 必须 | 不可删 |
| `tailwind.config.js` | Tailwind 扫描与主题配置 | 必须 | 不可删 |
| `postcss.config.js` | PostCSS/Tailwind 构建配置 | 必须 | 不可删 |
| `Dockerfile` | 前端容器镜像构建 | 生产部署必须 | 仅不使用容器部署时可删 |
| `nginx.conf` | 容器内 Nginx 静态站点配置 | 生产部署必须 | 同上 |
| `.env.example` | 环境变量模板 | 建议必须 | 建议保留 |
| `.env` | 本地开发环境变量 | 非必须（运行常用） | 可保留本地，不应入库 |
| `.dockerignore` | Docker 构建时忽略文件 | 建议保留 | 不建议删 |
| `node_modules/` | 本地依赖安装目录（约 345MB） | 非必须（可重装） | 可直接删除后 `npm install` 重建 |
| `dist/` | 前端构建产物（约 109MB） | 非必须（可重建） | 可直接删除后 `npm run build` 重建 |
| `vite.config.js` | 与 `vite.config.ts` 重复的历史文件（且 `.gitignore` 已忽略） | 非必须 | **建议删除** |

## 2. src 目录（源码）

## 2.1 入口与路由（必须）

| 路径 | 作用 | 是否必须 | 删除建议 |
|---|---|---|---|
| `src/main.tsx` | React 挂载入口，加载全局样式与路由 | 必须 | 不可删 |
| `src/App.tsx` | 全站路由、鉴权路由、旧路由兼容重定向 | 必须 | 不可删 |
| `src/vite-env.d.ts` | Vite 类型声明 | 必须 | 不可删 |

## 2.2 页面层（pages/，业务必须）

- `src/pages/*.tsx`：对应各业务页面（登录/注册/博客/饮食/姿态/管理等），属于业务功能主体，默认都必须。
- `src/pages/poseTool/*`：姿态工具核心 UI 与报告拼装，必须。

删除规则：
- 只有在“功能下线 + 路由移除 + API 解绑 + 测试通过”同时满足时，页面文件才可删。

## 2.3 组件层（components/）

| 路径 | 作用 | 是否必须 | 删除建议 |
|---|---|---|---|
| `src/components/Layout.tsx` | 全站布局容器 | 必须 | 不可删 |
| `src/components/Navbar.tsx` | 顶部导航 | 必须 | 不可删 |
| `src/components/Footer.tsx` | 页脚 | 建议保留 | UI 改版后可替换 |
| `src/components/BackToTop.tsx` | 返回顶部交互 | 可选 | 可按 UI 策略删除 |
| `src/components/FeedbackDrawer.tsx` | 反馈抽屉 | 可选偏重要 | 若取消反馈入口可删 |
| `src/components/OrganicFluidBackground.tsx` | 背景装饰组件 | 可选 | 性能/视觉调整时可删 |
| `src/components/ui/*` | 复用 UI 原子组件 | 建议保留 | 被完全替代后可删 |

## 2.4 状态与 API 层（必须）

| 路径 | 作用 | 是否必须 | 删除建议 |
|---|---|---|---|
| `src/state/auth-context.tsx` | 登录态上下文 | 必须 | 不可删 |
| `src/lib/api.ts` | 通用 API 客户端 | 必须 | 不可删 |
| `src/lib/auth.ts` | 鉴权相关客户端逻辑 | 必须 | 不可删 |
| `src/lib/food/api.ts` | 饮食模块 API | 对应功能必须 | 功能下线才可删 |
| `src/lib/poseApi.ts` | 姿态模块 API | 对应功能必须 | 功能下线才可删 |

## 2.5 姿态算法层（lib/pose/）

- `src/lib/pose/*` 基本都为实时/离线分析核心逻辑，默认必须。
- 明确候选：`src/lib/pose/realtimePullupLegacy.ts` 当前未发现被引用，可作为“候选删除文件”。

删除前检查：
1. `rg realtimePullupLegacy src` 确认零引用。
2. 运行 `npm run typecheck` 与关键页面手测通过。

## 2.6 样式层（styles/）

| 路径 | 作用 | 是否必须 | 删除建议 |
|---|---|---|---|
| `src/styles.css` | 全局样式与 Tailwind 指令 | 必须 | 不可删 |
| `src/styles/tokens.css` | 设计令牌变量 | 建议必须 | 不建议删 |
| `src/styles/ui-components.css` | UI 组件样式增强 | 建议必须 | 替换后再删 |
| `src/styles/food-module.css` | 饮食模块样式 | 视页面依赖 | 先查引用再删 |

## 3. public 目录（静态资源）

## 3.1 必须保留（当前有直接引用）

| 路径 | 作用 | 说明 |
|---|---|---|
| `public/favicon.png` | 站点图标 | `index.html` 引用 |
| `public/assets/css/*` | 全局样式库（bootstrap/main 等） | `index.html` 多个 `<link>` 直接引用 |
| `public/assets/images/*` | 页面图片（home/about/blog/food/pose/bg 等） | 多页面字符串路径直接引用 |
| `public/assets/models/movenet/*` | 姿态检测模型文件 | `movenetPose.ts` 默认路径引用 |
| `public/assets/fonts/*` | 字体资源 | 被全局 CSS 引用（间接） |
| `public/figma/icon-*.svg` | 博客页图标 | `BlogListPage.tsx` 直接引用 |

## 3.2 可条件删除（先审计引用）

- `public/assets/images` 下大量历史模板图：可能被 `main.css` 或页面 fallback 引用，不能只看 TSX 明文。
- `public/assets/css/main.css.map`：仅调试 sourcemap，生产可删（若不需要前端样式调试）。

## 4. 可直接删除清单（本次审计）

- `frontend/node_modules/`（可重装）
- `frontend/dist/`（可重建）
- `frontend/vite.config.js`（与 `vite.config.ts` 重复，历史遗留）

## 5. 暂不建议删除清单

- `public/assets/css/*`（入口强依赖）
- `public/assets/models/movenet/*`（姿态功能强依赖）
- `src/pages/*`、`src/lib/*`（业务核心）

## 6. 安全清理执行顺序（建议）

1. 先删除 `dist` 和 `node_modules` 释放空间（不影响仓库逻辑）。
2. 删除 `vite.config.js` 并执行 `npm install && npm run typecheck && npm run build`。
3. 补齐 `figma` 缺失占位图或改为已有资源路径。
4. 再进行第二轮“按引用删图”精简 `public/assets/images`。
