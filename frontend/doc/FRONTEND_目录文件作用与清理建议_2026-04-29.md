# frontend 目录文件作用与清理建议（2026-05-05）

- 目录：`E:\trae_project\AI-FIT\frontend`
- 口径：以当前源码结构为准，旧的 `src/lib/pose/*`、`src/lib/food/*`、`src/pages/*.tsx` 平铺形态已退役。
- 目标：说明主要目录职责，并给出保留/清理边界。

| 路径 | 作用 | 删除建议 |

| `node_modules/` | 本地依赖下载目录 | 可删，可由 `npm install` 重建 |
| `dist/` | 构建产物 | 可删，可由 `npm run build` 重建 |

## 3. `lib/` 保留原则

`src/lib/` 现在只保留真正跨业务复用的基础设施：

- `api.ts`：通用 API 请求封装。
- `auth.ts`：通用鉴权客户端能力。
- `media.ts`：跨页面可复用媒体工具。
- `report/print.ts`、`report/unified.ts`：跨业务报告打印与归一化。

不应再把 Pose/Food 这类业务实现放进 `lib/`。业务代码应进入对应 `src/modules/<domain>/`。

## 4. Pose 当前主链路

Pose 已收敛为：

- `modules/pose/domain/`：动作定义、训练命名等领域常量。
- `modules/pose/vision/`：MoveNet、绘制、实时 provider、底层视觉能力。
- `modules/pose/analyzer/`：四个动作 analyzer 与共享反馈类型。
- `modules/pose/runtime/`：live/offline 两条 runtime 主入口及私有 helper。
- `modules/pose/reporting/`：报告类型、归档 payload、policy stamp、overlay replay。
- `modules/pose/helpers/`：报告生成、policy rules、建议映射等 Pose 私有业务 helper。

页面只调用 runtime hook 和展示组件，不直接连接 MoveNet/analyzer/低层 session。

## 5. 清理建议

可直接清理：

- `node_modules/`
- `dist/`

需审计后清理：

- `public/assets/images/*`
- 历史主题 CSS 中未使用资源
- 未被路由和 import 引用的旧文档

不可恢复旧结构：

- 不再新增 `src/lib/pose/*` 或 `src/lib/food/*`。
- 不再新增平铺 `src/pages/*.tsx`。
- 不再让页面直接 import `modules/pose/vision/*` 或 `modules/pose/analyzer/*`。
