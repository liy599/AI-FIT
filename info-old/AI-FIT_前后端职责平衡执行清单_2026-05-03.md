# AI-FIT 前后端职责平衡执行清单（2026-05-03）

## 1. 目标定义
- 目标：让每个功能点都满足“前端负责展示与编排，后端负责规则与一致性”的边界。
- Pose 特殊约束：默认且唯一推理路径为本地分析，视频不出本地；服务端视频分析能力已下线。

## 2. 模块级职责矩阵（As-Is -> To-Be）

| 模块 | 当前主要承载 | 目标承载 | 结论 |
|---|---|---|---|
| 认证/会话 | 后端（Cookie+CSRF）+ 前端视图态 | 后端主导、前端仅展示态 | 已基本达标 |
| 路由与页面壳层 | 前端 | 前端 | 达标 |
| 博客/评论/饮食/用户资料 | 后端规则 + 前端编排 | 保持 | 达标 |
| 数据生命周期/管理员能力 | 后端规则 + 前端管理页 | 保持 | 达标 |
| Pose 实时/离线本地 | 前端本地推理 + policy 驱动规则 + 后端记录 | 前端本地计算 + 后端策略下发/记录 | 已达标（持续校准规则） |

## 3. Pose 隐私边界（强制）

### 3.1 默认路径
- `mode=offline` 下执行本地分析，不上传原始视频。
- UI 默认文案明确：本地优先、隐私优先。

### 3.2 后端上传入口下线
- `/api/pose/videos*` 不可用。
- `/api/pose/analysis/tasks*` 不可用。
- `/api/pose/server-analysis*` 不可用。
- 后端只接收训练摘要 JSON 与报告 JSON，不接收 Pose 原视频。

### 3.3 验收标准
- Pose 原视频上传与服务端分析入口必须返回 404。
- 本地模式完整可用（上传/分析/报告）且不触发服务端视频上传接口。

## 5. DoD（完成判定）
- 职责：每个功能有明确 owner（前端展示编排 / 后端规则一致性）。
- 隐私：Pose 默认本地；后端不提供 Pose 原视频上传或服务端分析入口。
- 质量：关键链路有回归测试或可执行手测清单。
- 文档：功能清单与代码一致，无过时文件路径。
