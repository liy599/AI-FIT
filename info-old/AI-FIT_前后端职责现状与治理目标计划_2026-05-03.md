# AI-FIT 前后端职责现状、治理目标与实施计划（2026-05-03）

## 1. 背景与目标
本文件用于固化 AI-FIT 当前前后端职责分配现状，并给出后续治理目标与执行计划。
核心目标：
- 职责分配清晰、边界稳定、演进可控。
- 满足优秀工程实践（安全、可维护、可测试、可扩展）。
- 对 Pose 模块执行隐私优先策略：`视频不出本地（默认/优先前端本地处理）`。

## 2. 当前职责现状（基于现有代码）

### 2.1 前端已承担职责
- 页面壳层与路由编排：`App.tsx`、`Layout.tsx`、Navbar/Footer 等。
- 会话视图态：`auth-context.tsx`（服务端会话驱动，前端只管理 user 视图态）。
- 功能页面编排：Blog/Food/Profile/Pose 各页面状态流转与交互。
- Pose 实时/离线（本地）较重逻辑：动作分析、反馈拼装、前端报告呈现。

### 2.2 后端已承担职责
- 认证与权限：`HttpOnly Cookie + CSRF`、管理员能力、JWT 校验。
- 业务数据与规则：用户、博客、评论、饮食、训练记录、数据生命周期。
- 安全能力：限流、上传访问控制、鉴权拦截、生产配置校验。
- 可选服务端 Pose 异步分析接口与 worker（已存在）。

### 2.3 现状评价
- 优点：认证安全职责已正确下沉后端；通用业务基本是后端主导。
- 问题：Pose 相关业务规则与流程控制仍偏前端；部分大页面存在“编排+规则+展示”耦合。
- 结论：整体中等偏好，但局部（Pose）仍前端偏重，需要继续治理。

## 3. 目标职责分配模型（To-Be）

### 3.1 前端职责（必须）
- 交互与展示：页面渲染、状态展示、流程引导、可访问性与体验。
- 轻量编排：调用后端 API、处理 UI 层错误态。
- 本地隐私计算：Pose 视频本地分析（默认路径）。

### 3.2 后端职责（必须）
- 认证鉴权、权限控制、会话安全。
- 业务规则与数据一致性（持久化、约束、审计、限流）。
- 管理端策略配置与可观测性。

### 3.3 禁止职责（边界约束）
- 前端不得实现需要全局一致性的核心业务规则（应下沉后端或共享策略配置）。
- 后端不得在未显式用户授权情况下接收 Pose 原始视频（遵循本地优先）。

## 4. Pose 隐私边界（硬性要求）

### 4.1 强约束
- 默认路径：前端本地处理视频与姿态分析，原始视频不上传后端。
- 服务端推理必须是“显式开关 + 明确文案 + 用户主动确认”后才允许。
- 若开启服务端路径，必须在 UI 中明确告知数据流向、用途和保留策略。

### 4.2 技术落地要求
- 前端：默认仅走本地分析链路；服务端入口隐藏或二次确认。
- 后端：服务端 Pose 接口保留鉴权、限流、生命周期清理与访问审计。
- 文档：用户手册与隐私说明必须明确“默认本地处理”。

## 5. 治理目标（质量标准）

### 5.1 架构目标
- 页面层只负责展示与流程编排。
- 业务规则集中在后端（或后端下发策略，前端仅执行）。
- 前后端接口契约稳定（字段、错误码、状态语义一致）。

### 5.2 工程目标
- 高风险链路（认证、权限、删除、隐私）有可回归测试。
- 关键页面具备加载态/错误态/空态一致模板。
- 文档与实现一致，过时条目不残留。

### 5.3 隐私目标
- Pose 默认“视频不出本地”成为发布基线。
- 若有服务端分析能力，需可禁用且默认关闭（生产策略可控）。

## 6. 分期实施计划

### Phase 1（立即，1-3 天）
- 完成职责边界文档与模块清单更新（本文件 + 功能清单）。
- 梳理 Pose 前端规则点，标记“应下沉/应策略化”列表。
- 在 UI 文案中显式强调 Pose 默认本地处理。

### Phase 2（短期，3-7 天）
- 将可配置规则从前端硬编码迁移为后端策略下发（阈值、时长、开关）。
- 为敏感流程补最小测试：认证会话、管理员权限、数据删除、Pose 隐私路径。
- 清理页面中的业务耦合逻辑，提取到 feature/service 层。

### Phase 3（中期，1-2 周）
- 完成 Pose 双路径治理：
  - 本地路径：默认、稳定、可观测。
  - 服务端路径：可选、明确授权、审计可追踪。
- 建立前后端契约校验清单（接口字段/错误语义/兼容策略）。

## 7. 验收标准（DoD）
- 职责边界：每个功能可明确指出“前端职责/后端职责/共享策略”。
- 隐私基线：Pose 默认本地处理，未授权不上传视频。
- 安全基线：会话、CSRF、权限、限流链路回归通过。
- 文档基线：功能清单与代码一致，无过时组件/路径引用。

## 8. 下一步执行建议（从现在开始）
1. 先做 Pose 规则清单（阈值、校验、提示语）并标注“前端保留”与“后端下发”。
2. 再做接口契约表（输入/输出/错误码）统一，避免页面各自处理错误语义。
3. 最后补回归测试最小集，保证后续改造可持续。
