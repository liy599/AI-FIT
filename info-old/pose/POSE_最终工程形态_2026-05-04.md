# Pose 最终工程形态与交付说明（2026-05-04）

## 1. 当前结论

- Pose 当前主链路只保留四个前端可达动作：`squat`、`pushup`、`bent-over-row`、`lateral-raise`。
- 默认且唯一主推理路径为浏览器本地推理：实时摄像头流和离线原视频都不上传后端。
- 后端不再提供 Pose 原视频上传、服务端分析任务或服务端逐帧推理接口。
- 前端按职责收口：页面负责路由与布局，`components/pose` 负责展示，`modules/pose` 承载业务、runtime、vision、analyzer、reporting，`lib/` 只保留跨业务基础设施。

## 4. 已下线或清理内容

- `pullup`、`bench press`：当前前端不可达，相关默认动作白名单和主链路已移除。
- `generic motion`、MediaPipe 33-point 旧链路、motion-standard 对比链路：不在当前交付主链路中。
- `frontend/src/lib/pose/*`：已删除，Pose 专属能力迁入 `frontend/src/modules/pose/*`。
- `frontend/src/lib/food/*`：已删除，Food 业务迁入 `frontend/src/modules/food/*`。
- `frontend/src/modules/pose/tool/*`：已删除，拆入 `runtime/` 与 `reporting/`。
- `/api/pose/videos*`、`/api/pose/analysis/tasks*`、`/api/pose/server-analysis*`：服务端视频分析入口已下线。
- `backend/app/services/pose/server_inference_worker.py`：旧服务端视频分析 worker 已删除。

## 5. 工具页内部收口结果

- `PoseToolPage.tsx`：只保留页面状态、模式切换、用户操作入口和组件装配。
- `modules/pose/runtime/live.ts`：实时模式主 hook，集中摄像头、MoveNet RAF 检测、analyzer、overlay、报告和训练保存。
- `modules/pose/runtime/offline.ts`：离线模式主 hook，集中本地文件、抽帧分析、overlay 回放、报告和归档。
- `modules/pose/runtime/live/*`：实时模式私有 helper，不对页面公开。
- `modules/pose/runtime/offline/*`：离线模式私有 helper，不对页面公开。
- `modules/pose/helpers/replayStats.ts`：四动作离线视频报告共用的 analyzer replay 统计。
- `modules/pose/policy.ts` 与 `helpers/policyRules.ts`：统一 policy runtime rules、fallback 与 analyzer tuning 解析。

## 6. 后端职责边界

- `/api/pose/policy`：下发版本化策略、动作白名单、隐私规则、实时/离线限制和四动作规则口径。
- `/api/pose/trainings`：接收训练摘要 JSON，保存 policy version 与报告摘要，不接收原视频。
- 后端不参与 Pose 推理，不接收 Pose 原始视频。

## 7. 验证结果

- 前端构建：`npm.cmd run build` 通过。
- 前端边界检查：`npm.cmd run lint:boundaries` 通过。
- 后端回归：`.\.venv\Scripts\pytest.exe tests` 通过。
- 残留扫描：代码中无旧 `frontend/src/lib/pose`、`frontend/src/lib/food`、`frontend/src/modules/pose/tool` 主链路引用。

## 8. 交付口径

- 默认且唯一主推理路径为浏览器本地推理。
- 前后端职责边界清晰：后端主导规则版本、鉴权、审计和持久化；前端主导本地推理、实时交互、可视化和报告生成。
- 当前只保留用户可达四动作主链路，避免旧动作、旧上传链路和历史实验实现继续混杂。
