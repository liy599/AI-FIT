# Pose 最终可交付治理目标（2026-05-04）

## 1. 完成定义
- 默认本地推理：摄像头流与离线原视频不上传，服务端分析默认关闭。
- 显式授权：服务端分析只有在开关开启且用户 consent 后才允许提交。
- 职责清晰：前端负责本地推理、实时状态机、交互与可视化；后端负责 policy 版本、规则口径、持久化、鉴权与审计。
- 规则可治理：当前四动作核心阈值进入 `/api/pose/policy` 或集中 defaults，不在页面和报告函数中散落。
- 报告可复现：训练摘要携带 policy version，同一输入在同一策略版本下输出一致。
- 可验收：自动化测试覆盖 policy、consent、训练摘要落库回显；手测脚本覆盖本地隐私链路。

## 2. 当前最终范围
- 用户可见动作：`squat`、`pushup`、`bent-over-row`、`lateral-raise`。
- 已下线/不在当前交付范围：pullup、bench press、generic motion、MediaPipe 33 点旧链路、motion-standard 对比链路。
- 交付主文档：`info/pose/POSE_最终工程形态_2026-05-04.md`。

## 3. 目标目录边界
- `frontend/src/pages/PoseToolPage.tsx`：页面装配、模式切换、UI 状态与用户操作入口。
- `frontend/src/modules/pose/index.ts`：页面级 pose module facade，禁止页面深挖底层 lib。
- `frontend/src/modules/pose/helpers/*`：纯计算、报告生成、四动作 analyzer 工厂、policy runtime rule 解析。
- `frontend/src/modules/pose/tool/*`：Pose 工具页编排 hook、保存 payload、replay、policy 消费、离线分析流程。
- `frontend/src/components/pose/*`：Pose 专属展示组件。
- `frontend/src/lib/pose/*`：MoveNet、四动作实时 analyzer、绘制、训练命名等当前主链路底层能力。
- `backend/app/routes/pose.py`：policy、训练记录、服务端分析授权与审计入口。

## 5. 发布门槛
- `frontend npm run build` 必须通过。
- `backend/tests/test_pose.py` 必须通过。
- 默认本地推理，抓包不得出现原视频上传到服务端分析接口。
- 服务端分析默认关闭；consent 缺失时请求必须失败。
- policy version 在前端可见，并随训练摘要落库和历史回显。
- 文档中的入口文件必须与现有代码一致，无已删除文件作为当前链路。
