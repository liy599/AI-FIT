# Pose 最终工程形态与交付说明（2026-05-04）

## 1. 当前结论
- Pose 当前主链路已收敛为四个前端可见动作：`squat`、`pushup`、`bent-over-row`、`lateral-raise`。
- 默认全程本地推理：实时摄像头流与离线原视频不上传；服务端分析默认关闭，开启时必须显式 consent。
- 目录按职责收敛：页面负责编排，`components/pose` 只做展示，`modules/pose` 承载业务与工具页流程，`lib/pose` 承载 MoveNet 与四动作 analyzer 底层能力，后端负责 policy、鉴权、审计和训练摘要持久化。
- 已清理当前主链路无关动作和历史实现：pullup、bench press、generic motion、MediaPipe 33 点旧链路、motion-standard 对比链路。

## 4. 已下线或清理内容
- `pullup`：当前前端不可见，相关 analyzer/report/policy 默认动作白名单已移除。
- `bench press`：当前前端不可见，旧图片与旧 analyzer 残留已移除。
- `generic motion`：未进入当前交付主链路，已移除。
- `MediaPipe 33-point` 旧链路：当前统一保留 MoveNet 17 点主链路，旧入口已移除。
- `motion-standard` 对比链路：未进入当前用户可达流程，已移除。
- `frontend/src/features`：旧 feature 目录已下线，统一迁移到 `frontend/src/modules`。

## 5. 工具页内部收敛结果
- `PoseToolPage.tsx`：只保留页面状态、模式切换、用户操作入口和组件装配。
- `modules/pose/tool/shared.ts`：集中工具页常量、错误文案、模式解析、离线任务 UI 文案、教学文案。
- `modules/pose/tool/liveSession.ts`：集中实时报告、实时 session summary、停止/重置状态、训练保存 payload。
- `modules/pose/tool/liveDetectionSession.ts`：集中摄像头与 MoveNet RAF 检测循环。
- `modules/pose/tool/offlineAnalysisPipeline.ts`：集中离线 MoveNet 提取、动作报告构建、replay 数据生成。
- `modules/pose/tool/useOfflinePoseAnalysis.ts`：只负责 hook 状态编排和本地归档调用。
- `modules/pose/helpers/policyRules.ts`：集中 policy runtime rules、阈值 fallback、analyzer tuning 解析。
- `modules/pose/helpers/analyzers.ts`：集中四动作 analyzer 创建与配置。

## 6. 后端职责边界
- `/api/pose/policy`：下发版本化策略、动作白名单、隐私规则、实时/离线限制和四动作规则口径。
- `/api/pose/trainings`：接收训练摘要 JSON，保存 policy version 与报告摘要，不接收原视频。
- `/api/pose/server-analysis/submit`：默认不可用；只有服务端开关开启且用户显式 consent 时允许提交。
- 后端不参与默认本地推理，不要求用户上传原始视频。

## 7. 验证结果
- 前端构建：`frontend npm.cmd run build` 通过。
- 后端 Pose 回归：`backend .\.venv\Scripts\pytest.exe tests\test_pose.py`，`11 passed`。
- 残留扫描：当前 `frontend/src`、`backend/app`、`backend/tests` 无 pullup/bench/generic/MediaPipe/motion-standard 活动引用。
- 已知非阻断项：Vite 仍提示 TensorFlow backend vendor chunk 超过 500 KB；当前已按路由懒加载，后续可继续做加载体验专项治理。

## 8. 交付口径
- 默认本地推理与隐私边界满足要求。
- 前后端职责边界清晰，后端主导规则版本、鉴权、审计和持久化，前端主导本地推理、实时交互、可视化与摘要生成。
- 当前只保留用户可达四动作主链路，避免旧动作和历史实现混杂。
- 文档、构建、回归测试已与当前代码状态对齐。
