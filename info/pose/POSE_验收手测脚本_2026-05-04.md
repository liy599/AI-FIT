# POSE 验收手测脚本（2026-05-04）

## 1. 目标
- 验证默认且唯一推理路径为本地推理，policy 版本追踪、训练摘要落库与回显一致性。
- 覆盖当前用户可达四动作：`squat`、`pushup`、`bent-over-row`、`lateral-raise`。

## 2. 前置条件
- 前端已启动：`frontend` Vite dev server 可访问。
- 后端已启动：`backend` API 可访问。
- 已登录一个普通用户账号。
- 浏览器 DevTools Network 面板已打开，并勾选 Preserve log。

## 3. Case A：默认本地推理，不上传原视频
1. 打开任一 Pose 动作的 `Video Analysis` 页面。
2. 选择本地视频，点击 `Analyze Locally`。
3. 观察 Network 请求。
4. 期望结果：
   - 允许出现 `/api/pose/policy`、`/api/pose/trainings` 等摘要/策略请求。
   - 不允许出现 Pose 原视频上传请求。
   - 页面能完成本地分析、显示 overlay 和报告。

## 4. Case B：后端上传入口已下线
1. 手动请求 `/api/pose/videos`。
2. 手动请求 `/api/pose/analysis/tasks`。
3. 手动请求 `/api/pose/server-analysis/submit`。
4. 期望结果：
   - 三类接口均不可用（404）。
   - 默认本地分析不受影响。

## 5. Case C：policy 版本可追踪
1. 打开 Pose live 或 video 页面。
2. 检查页面隐私与 policy 文案。
3. 期望结果：
   - 可见 policy version。
   - 可见 local-only inference enforced。

## 6. Case D：训练摘要落库与回显一致
1. 完成一次 live 或 offline 分析并保存训练记录。
2. 进入 Training History 列表与报告详情页。
3. 期望结果：
   - 列表出现新记录。
   - 详情中的 reps、accuracy、top issues 与保存前摘要一致。
   - 报告保留 policy version。

## 7. Case E：四动作入口一致性
1. 依次打开 `squat`、`pushup`、`bent-over-row`、`lateral-raise`。
2. 分别进入 Guide、Live Coaching、Video Analysis、Training History。
3. 期望结果：
   - 四动作入口均可达。
   - 不出现 pullup 或 bench press 入口。
   - 每个动作均能加载对应教学文案、教程视频路径和分析面板。

## 8. 通过标准
- A/B/C/D/E 全部通过。
- 任一用例失败即阻断发布，需修复后重新回归。

## 9. 自动化补充
- 前端构建：`frontend npm.cmd run build`。
- 后端 Pose 回归：`backend .\.venv\Scripts\pytest.exe tests\test_pose.py`。
