# Push-Up（俯卧撑）对齐 Deep Squat 实现程度：最终总结与改动守则

日期：2026-04-11

## 0. 适用范围与目标

本文件用于约束与指导：在 AI-FIT 项目中将 `pushup`（俯卧撑）补齐到与 `squat`（深蹲）一致的“实现程度”。

这里的“实现程度一致”分两层：

1. **工程闭环一致**：实时 + 离线都走“动作专用 Analyzer + 离线重放 + 专用报告”闭环，页面入口不再禁用，训练记录可归档。
2. **判定口径接近一致**：Analyzer 具备深蹲同级别的“状态机 + 规则判定 + 质量门控 + 会话聚合 + 原因码/纠正建议”能力，而不是“只要完成动作就算正确”。

## 1. 强约束（必须遵守）

### 1.1 不允许突破既有前端契约

1. **不得修改 `RealtimeFeedback` 类型结构**（字段名/层级/含义保持兼容）。
2. **不得要求页面新增 UI 字段**，只能让页面读取既有字段时表现更准确。
3. **不得新增新的“通用占位离线分析”分支**替代专用实现。

### 1.2 离线分析强约束（来自 info/pose）

1. 离线分析必须复用对应实时 Analyzer。
2. 每个动作必须有专用离线重放分析函数。
3. 每个动作必须有专用报告生成函数。
4. 禁止 `analyzeGenericMotion()` 作为新动作离线实现。

（对齐来源：`视频分析实现说明与动作扩展指南_2026-04-11.md`、`视频分析新动作接入最小改动清单_2026-04-11.md`）

### 1.3 实时分析强约束（来自 info/pose）

1. 新动作接入实时分析必须与深蹲范式一致，禁止“只加文案不加 Analyzer”。
2. 新动作 Analyzer 至少包含：
   - 状态机计次
   - 至少 2 条动作专用规则（幅度阈值 + 持续帧阈值）
   - 与 `RealtimeFeedback` 语义一致的输出

（对齐来源：`新动作接入最小改动清单_2026-04-11.md`、`深蹲实时检测实现说明与动作扩展指南_2026-04-11.md`）

## 2. 当前状态（作为基线）

截至本文件生成时，pushup 已满足“工程闭环一致”，但尚未满足“判定口径接近一致”：

### 2.1 已对齐（闭环层）

1. 已有专用离线重放与专用报告：
   - `buildPushupVideoLiveStyleReport()`
   - `buildPushupAlignedReport()`
2. `PoseToolPage`：
   - 实时：pushup 走专用 aligned report，并采集帧级统计数据
   - 离线：pushup 已加入专用离线白名单，且离线重放可分发到 pushup 专用函数

### 2.2 未对齐（判定深度层）

pushup 的 `RealtimePushupAnalyzer` 仍偏简化：

1. 计次规则较松，缺少回差/最小帧数等稳定性策略。
2. rep 质量判断不足：缺少 `unassessed/incorrect` 口径与持续帧硬阈值。
3. 原因码/原因标签/纠正建议未形成与深蹲同级别的“rep 级结论沉淀”。
4. session 聚合统计项大多仍是占位值。

## 3. 目标实现形态（不得超过框架）

### 3.1 允许做的增强（只增强，不扩展契约）

只允许在 `realtimePushup.ts` 内部增强以下内容，并仍输出 `RealtimeFeedback`：

1. **状态机稳定性**：阈值回差（enter/exit）+ 最小帧数门槛 + 防抖。
2. **质量门控**：
   - trackingQuality 或 sideAlignment 低可信时：允许计次但标记 `unassessed`（使用 `session.unassessedReps?` 可选字段）。
   - 明确硬失败条件：深度不足、躯干失稳等，使用持续帧阈值判定，输出 `incorrect`。
3. **rep 级结论**：补齐 `lastRepReasonCodes/Labels/Corrections`，让报告与建议映射可稳定工作。
4. **会话统计**：补齐 session 内已有字段：
   - `depthInsufficientCount`
   - `forwardLeanCount/backwardLeanCount`（可映射为“塌腰/撅臀”两类之一或两者）
   - `sideViewWarningCount`
   - `avgRepDurationSec/fastRepCount/slowRepCount`（使用固定 analyzer fps 的策略）

### 3.2 不允许的改动

1. 不允许为 pushup 引入新的 `RealtimeFeedback` 字段或新的 report schema 版本要求。
2. 不允许在页面层做 pushup 专属 UI 改造来“配合” Analyzer。
3. 不允许把 pushup 的离线实现替换为通用分析或模板对比占位。

## 4. 关键字段语义约定（避免前端不匹配）

为保持框架兼容，pushup 继续使用 `RealtimeFeedback` 的既有字段名：

1. `kneeAngle`：对 pushup 表示 **Elbow Bend（肘角）**，用于深度判断与 secondary metric 展示。
2. `hipAngle`：对 pushup 表示 **Body Line / Trunk Line（身体线/躯干线相关角度）**，用于“塌腰/撅臀”等规则判断与展示。
3. `torsoAngle`：对 pushup 表示 **躯干相对水平/垂直的倾斜程度**（取现有实现口径，不要求改 UI）。
4. `offsetAngle`：对 pushup 表示 **侧视对齐程度（side alignment）**。

说明：字段名保持不变是为了不破坏页面与报告通用渲染逻辑。

## 6. 验收标准（必须满足）

### 6.1 实时验收

1. 稳定计次（不抖动、少误计）。
2. 至少 2 条俯卧撑专用规则能稳定触发（且为持续帧判定）。
3. `correct/incorrect/unassessed`（如启用）口径合理，session 统计正确。
4. `npm run typecheck` 通过。

### 6.2 离线验收

1. 离线分析不再禁用 pushup，且进入 pushup 专用重放函数。
2. 报告包含 pushup 专用指标与建议，不是通用占位。
3. 同一素材下，离线结论与实时口径一致（至少 reps 与主要 issues 类型一致）。
4. `npm run typecheck` 通过。

## 7. 每次修改前的自检清单（强制执行）

每次提交代码改动前，必须逐条确认：

1. 没有改动 `RealtimeFeedback` 类型结构。
2. pushup 仍输出 `kneeAngle/hipAngle/torsoAngle/offsetAngle/trackingQuality` 等既有字段。
3. 离线分析仍复用 `RealtimePushupAnalyzer`，且不走通用占位分析。
4. 任何新增 issue 文案都能被 `mapSuggestionFromIssue(..., 'pushup')` 覆盖。
5. 前端 `typecheck` 通过。
