# 稳定版实时与视频分析深蹲实现（前端复刻手册）

日期：2026-04-12（按当前仓库实现更新）  
适用目标：仅依靠本文档，复现 AI-FIT 网站上当前已应用的“深蹲实时分析 + 深蹲视频分析”前端实现。

“若参照本文档扩展其他动作，请在实现过程中优先保证可扩展性与模块隔离，确保单个动作的参数、状态机、判定与绘制变更不会影响其他已上线动作的行为与口径。”

## 1. 复刻范围与边界

本手册只覆盖“当前线上前端真实在用”的深蹲逻辑。

包含：

1. 实时模式（Live）深蹲分析。  
2. 视频模式（Offline）深蹲分析。  
3. 与深蹲相关的阈值、状态机、报告生成、训练归档接口调用。  
4. Overlay 显示切换（`Full 17` / `Midline`）。

不包含：

1. 后端异步视频任务流（`/api/pose/videos`、`/api/pose/analysis/tasks`）在页面主链路中并未使用。  
2. 其他动作（pushup、pullup、bench-press、lateral-raise）的细则实现。

---

## 2. 当前真实实现的核心结论

1. 深蹲实时和深蹲视频回放都使用 `RealtimeSquat17Analyzer`。  
2. 深蹲判定只按 MoveNet 17 点 `nativeKeypoints` 进行；不再使用 33 点作为深蹲判定输入。  
3. 实时与视频的 tempo 阈值已拆分：
- 实时：`repFastSec=1.2`，`repSlowSec=4.2`
- 视频：`repFastSec=1.5`，`repSlowSec=4.2`
4. Overlay 按钮为 `Full 17` 与 `Midline`：只影响前端绘制，不影响分析结果。  
5. 后端只负责配置与训练记录存储，不参与逐帧判定。

## 4. 深蹲关键常量与默认参数（必须一致）

### 4.1 Analyzer 内部默认（`realtimeSquat17.ts`）

判定类默认（实时基线）：

1. `kneeForwardWarnRatio = 0.048`  
2. `kneeForwardFailRatio = 0.053`  
3. `kneeForwardFailMinFrames = 1`  
4. `forwardLeanWarnDeg = 30`  
5. `forwardLeanFailDeg = 32`  
6. `forwardLeanFailMinFrames = 2`  
7. `trackingQualityMin = 0.28`

时序/门控：

1. `REP_COUNT_MIN_FRAMES = 4`  
2. `REP_VALID_MIN_FRAMES = 8`  
3. `REP_VALID_RATIO_MIN = 0.45`  
4. `LOWER_BODY_QUALITY_MIN = 0.35`  
5. `SIDE_VIEW_WARN_ANGLE = 65`  
6. `SIDE_VIEW_BAD_RATIO_MAX = 0.55`  
7. `KNEE_ANGLE_CORRECTION_DEG = 8`

状态机角度阈值：

1. `S1_ENTER=150`，`S1_EXIT=145`  
2. `S3_ENTER=110`，`S3_EXIT=118`

### 4.2 实时与视频 tempo 分离（`realtimeSquat17.ts`）

1. `REALTIME_DEFAULT_SQUAT17_TEMPO = { repFastSec: 1.2, repSlowSec: 4.2 }`  
2. `VIDEO_DEFAULT_SQUAT17_TEMPO = { repFastSec: 1.5, repSlowSec: 4.2 }`

### 4.3 视频失败阈值默认（`poseToolHelpers.ts`）

`VIDEO_DEFAULT_SQUAT17_TUNING`：

1. `kneeForwardWarnRatio: 0.050`  
2. `kneeForwardFailRatio: 0.065`  
3. `kneeForwardFailMinFrames: 2`  
4. `forwardLeanWarnDeg: 40`  
5. `forwardLeanFailDeg: 54`  
6. `forwardLeanFailMinFrames: 2`  
7. `trackingQualityMin: 0.28`

说明：页面会尝试从后端 `GET /api/pose/config/squat17-tuning` 拉配置，覆盖视频失败阈值。

## 5. 实时深蹲（Live）复刻步骤

### 5.1 生命周期与初始化

在 `PoseToolPage`：

1. `LIVE_TARGET_FPS = 40`，`LIVE_TARGET_FRAME_MS = 1000/40`。  
2. `startLive()` 内：
- `analyzerRef = createAnalyzer('squat')`（返回 `RealtimeSquat17Analyzer`）
- `setTuning(liveSquatTuning)`
- `setTempo(REALTIME_DEFAULT_SQUAT17_TEMPO)`
- `setAnalyzerFps(40)`
3. 初始化 `MoveNetStabilizer`、`DistanceTracker`。  
4. `createBestRealtimePoseProvider()` 创建 MoveNet Lightning 检测器。  
5. 打开摄像头，开始 `tick()` 循环。

### 5.2 每帧处理（关键）

在 `tick()` 中必须遵循：

1. `provider.detect(videoEl, frameTs)` 获取：
- `landmarks`（33 格式）
- `nativeKeypoints`（17 点）
2. 深蹲分支：
- 若 `nativeKeypoints` 有效 -> `analyzeNative(nativeKeypoints)`
- 若无效 -> 本帧直接 `return` 下次 RAF（不做 33 点回退判定）
3. 反馈后更新：
- `setFeedback(nextFeedback)`
- `liveIssueFreqRef / liveTimelineRowsRef / liveRepFindingsRef / liveTrackingQualitySamplesRef`
4. 绘制层：
- `drawModeRef.current === 'full17'` -> `drawPoseJoints17(...)`
- 否则 -> `drawMidpointSkeleton(...)`
5. 固定附加 `drawDistanceGuide(...)`。

### 5.3 Overlay 切换实现要求

1. 状态：`drawMode: 'full17' | 'midline'`。  
2. 按钮文案固定：`Full 17` / `Midline`。  
3. 必须使用 `drawModeRef` 读取最新模式，避免 `tick()` 闭包锁死旧值。

### 5.4 会话结束与保存

1. `stopLive()`：停循环、停相机、生成 `liveSessionSummary`。  
2. `saveTrainingRecord()`：调用 `createPoseTraining`，上传：
- `started_at/ended_at`
- `sets`
- `report`（来自 `buildSquatAlignedReport(source='live')`）

## 6. 视频深蹲（Offline）复刻步骤

### 6.1 入口限制

1. `OFFLINE_DEDICATED_REPLAY_ACTIONS = new Set(['squat'])`。  
2. 非深蹲动作直接提示不可用。

### 6.2 本地抽帧

`runOfflineAnalysis()`：

1. 文件大小限制 `<= 80MB`。  
2. 本地 `objectURL`，不上传服务器参与分析。  
3. 只调用 `extractPose33FromVideoUrlWithMoveNet(objectURL, { targetFps: 40 })`。  
4. 必须拿到 `nativeFrames`；若为空直接报错。

### 6.3 回放分析

调用 `buildSquatVideoLiveStyleReport(...)`：

1. 内部 `new RealtimeSquat17Analyzer()`。  
2. 下发：
- `setTuning(input.tuning ?? VIDEO_DEFAULT_SQUAT17_TUNING)`
- `setTempo(VIDEO_DEFAULT_SQUAT17_TEMPO)`
- `setAnalyzerFps(input.fps)`
3. 逐帧只在 `frame.landmarks && nativeFrame.keypoints.length>0` 时执行 `analyzeNative(...)`。  
4. 累积 `timelineRows / messageFreq / repFindings`。  
5. 最终走 `buildSquatAlignedReport(source='video', ...)`。

### 6.4 归档

本地报告成功后尝试 `createPoseTraining` 自动归档；失败不影响本地报告显示。

## 7. RealtimeSquat17Analyzer 规则口径（复刻必需）

### 7.1 状态机

1. `s1` 站立、`s2` 过渡、`s3` 底部。  
2. 必须先达到 `stableS1Frames>=6` 且 `stableValidFrames>=6` 才允许启动新 rep。  
3. 完整循环 `... -> s3 -> s1` 才尝试结算。

### 7.2 关键几何与质量

1. 使用左右侧置信度选择主侧，必要时做双侧 blend。  
2. `trackingQuality = primary*0.75 + secondary*0.15 + face*0.1`。  
3. `isCountingPaused` 条件：
- `trackingQuality < tuning.trackingQualityMin` 或
- `lowerBodyQuality < 0.35` 或
- `kneeVerticalAngle / torsoAngle` 不可计算

### 7.3 每 rep 判定

失败条件（在有效 side-view 下判定）：

1. `kneeForwardFailed`：峰值超过 `kneeForwardFailRatio` 且持续帧达到 `kneeForwardFailMinFrames`。  
2. `forwardLeanFailed`：峰值超过 `forwardLeanFailDeg` 且持续帧达到 `forwardLeanFailMinFrames`。  
3. `tempoFastFailed`：`repDurationSec < tempo.repFastSec`。  
4. `tempoSlowFailed`：`repDurationSec > tempo.repSlowSec`。

输出：

1. 任一失败 -> `incorrect`。  
2. 无失败 -> `correct`。  
3. 跟踪或视角不可靠 -> `unassessed`（计次但不纳入 accuracy 分母）。

## 8. 报告生成口径（必须复现）

### 8.1 统一报告函数

`buildSquatAlignedReport` 同时服务实时与视频，结构包含：

1. `summary`（total/effective/unassessed/correct/incorrect/accuracy/avgRep）  
2. `keyMetrics`（含 `formAccuracyPct`、`assessedRepPct`、`fast/slowRepCount`、`sideViewInvalidReps`、`effectiveFps`）  
3. `issues`（按 rep 失败统计 + frame 频次 + tempo 规则补充）  
4. `suggestions`  
5. `details.timelineSampled`、`details.repFindings`

### 8.2 Tempo 补充规则

报告层还有 timeline 二次 tempo 检测（`analyzeSquatTempoFromTimeline`），用于增强快慢与稳定性提示。

## 9. 后端接口职责（现状）

实际被主链路使用：

1. `GET /api/pose/config/squat17-tuning`（拉视频失败阈值）  
2. `PUT /api/pose/config/squat17-tuning`（管理员保存阈值）  
3. `POST /api/pose/trainings`（保存训练）  
4. `GET /api/pose/trainings`、`GET /api/pose/trainings/<id>`（历史与详情）

说明：

1. 后端默认 tuning 在 `pose.py` 为：`0.045/0.058/...`；前端视频 fallback 默认为 `0.050/0.065/...`。  
2. 页面若成功拉到后端配置，将覆盖前端视频失败阈值。

## 10. 参数优先级（按实际代码）

### 10.1 实时

1. `liveSquatTuning`（初始为 `REALTIME_DEFAULT_SQUAT17_TUNING`）  
2. `setTempo(REALTIME_DEFAULT_SQUAT17_TEMPO)` 固定实时 tempo

### 10.2 视频

1. `videoSquatTuning` 初始 `VIDEO_DEFAULT_SQUAT17_TUNING`  
2. 若后端配置可用，则按 `pickVideoFailureTuning` 覆盖失败阈值  
3. 传给回放分析时，强制 `trackingQualityMin` 对齐实时：
- `tuning.trackingQualityMin = liveSquatTuning.trackingQualityMin`
4. tempo 固定 `VIDEO_DEFAULT_SQUAT17_TEMPO`

## 11. 验收清单（复刻完成后的自测）

1. 进入深蹲实时页，按钮显示 `Full 17` 与 `Midline`。  
2. 切换 `Midline` 后，画面骨架变为中线简化，不再显示 17 点骨架。  
3. 深蹲实时分析断开 native keypoints 时，该帧不产出反馈（不会回退 33 点判定）。  
4. 离线深蹲只走 MoveNet 抽帧与 native 回放；非深蹲离线分析禁用。  
5. 实时快慢阈值与视频快慢阈值不同（1.2 vs 1.5）。  
6. 保存训练后，历史页可查看报告，字段含 `effectiveReps/unassessedReps/repFindings`。  
7. `npm run build` 通过。

## 12. 最小复刻伪代码

```ts
// Live
analyzer = new RealtimeSquat17Analyzer()
analyzer.setTuning(liveTuning)
analyzer.setTempo({ repFastSec: 1.2, repSlowSec: 4.2 })
analyzer.setAnalyzerFps(40)

loop each frame:
  detected = provider.detect(video)
  if (!detected.nativeKeypoints?.length) continue
  feedback = analyzer.analyzeNative(detected.nativeKeypoints)
  updateUi(feedback)
  draw(drawModeRef.current === 'full17' ? full17 : midline)

// Offline video
extracted = extractPose33FromVideoUrlWithMoveNet(videoUrl, { targetFps: 40 })
if (!extracted.nativeFrames.length) throw Error

analyzer = new RealtimeSquat17Analyzer()
analyzer.setTuning(videoTuning)
analyzer.setTempo({ repFastSec: 1.5, repSlowSec: 4.2 })
analyzer.setAnalyzerFps(extracted.fps)

for i in frames:
  if (!frames[i].landmarks || !nativeFrames[i]?.keypoints.length) continue
  feedback = analyzer.analyzeNative(nativeFrames[i].keypoints)
  collectMetrics(feedback)

report = buildSquatAlignedReport(...)
```
