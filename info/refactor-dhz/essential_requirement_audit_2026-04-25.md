## 三、问题清单（按严重级别）

## 高风险（必须先修）

1. 示例环境文件包含疑似真实密钥
- 证据：`backend/.env.example:26`, `backend/.env.example:29`
- 风险：密钥泄露、供应链与账户安全风险、合规风险。
- 建议：立即轮换相关密钥；仓库历史清理；示例文件改占位符。

2. 上传路径边界校验存在前缀绕过风险
- 证据：`backend/app/utils/upload_access.py:41`（`startswith(upload_root)`）
- 风险：在特定路径构造下可能出现目录逃逸误判。
- 建议：改为基于 `Path.resolve()` + `relative_to()` 的严格目录包含校验。

## 中风险（A 档关键扣分项）

3. 缺少数据库迁移体系
- 证据：`backend/app/__init__.py:19`, `backend/app/__init__.py:26`
- 风险：跨环境 schema 漂移、回滚困难、发布不可控。
- 建议：引入 Alembic/Flask-Migrate，建立版本化迁移流程。

4. 限流仅进程内内存实现，不支持多实例一致性
- 证据：`backend/app/utils/rate_limit.py:13`
- 风险：横向扩展后限流失效或不一致。
- 建议：迁移至 Redis 等共享存储。

5. 认证会话治理不完整（无 refresh/blacklist）
- 证据：`backend/app/routes/auth.py:79`, `info/project/PROJECT_STATUS.md:44`, `info/project/PROJECT_STATUS.md:347`
- 风险：长周期 token 风险暴露，主动失效能力不足。
- 建议：补 refresh token + 黑名单/版本戳失效机制。

6. 运行环境依赖较重，影响“低安装负担”验收项
- 证据：`scripts/dev.ps1:27`, `scripts/dev.ps1:31`, `scripts/dev.ps1:71`
- 风险：评审现场环境不可控，影响可移植性与可用性评分。
- 建议：提供容器一键全栈启动 + 在线演示环境/录屏兜底。

## 低风险（建议修复）

7. 开发入口默认 debug=True
- 证据：`backend/run.py:11`
- 风险：误用到非开发环境会带来信息暴露风险。
- 建议：按环境变量控制 debug，默认 false。

8. 默认数据库弱口令示例可能被误用
- 证据：`backend/db_init.sql:1`, `backend/db_init.sql:2`, `backend/app/config.py:27`
- 风险：新环境误配导致弱安全基线。
- 建议：示例仅保留占位符并在启动时强校验。
