# 课程要求精炼版（A 档目标）

## 1. 交付与需求匹配
- 软件必须完整满足客户需求。
- 项目必须按时交付。

## 2. 技术难度与创新
- 体现较高技术复杂度与实现难度。
- 对关键技术问题提供创新、创造性的解决方案。

## 3. 架构设计与模块化
- 系统设计清晰、结构合理。
- 模块边界明确，便于后续扩展与维护。

## 4. 文档完整性
- 文档需完整且结构清晰。
- 至少包含：代码组织说明、测试计划、用户手册。
- 用户手册内容必须与系统实际功能一致。

## 5. 质量属性要求
- 可靠性：运行稳定，不崩溃，不频繁报错。
- 可用性：面向非技术用户也应易于使用。
- 可维护性：代码组织清晰、可读、可持续更新。
- 性能：响应及时、资源使用高效。
- 安全性：具备防未授权访问与恶意攻击的基本能力。
- 可扩展性：数据量/用户量上升时仍保持可用。
- 可移植性：可在不同平台运行，且不需大改。

## 6. 测试评估（20%）
- 软件会被全面测试与评估。
- 团队需主动设计评估流程（例如通过 Web 界面可完整走查）。
- 用户手册必须提供可执行的使用与评测说明。
- 若评测流程不顺畅或说明不足，将被扣分。

## 7. 验收重点检查项
- 用户手册是否与系统一致。
- 登录等关键账号功能是否可用。
- 是否需要额外安装/下载（理想状态：不需要）。
- 系统目标与用途是否清晰。
- 是否具有明确客户导向并满足客户需求。
- 系统是否易用。
- 系统是否安全、可靠。
- 总体可用性是否良好。
- 技术实现难度是否足够。
- 是否存在突出、创新或有创造性的亮点。
- 是否仍有明显 bug 或缺失功能。

## 8. A 档判定摘要
- 完整满足客户需求并按时交付。
- 技术实现复杂且有创新。
- 架构清晰、模块化良好、可维护。
- 文档全面，代码/测试计划/用户手册齐全。
- 系统可靠、高效、可扩展，无重大缺陷。
- 整体达到专业软件工程质量标准。

## 9. 结项自查清单（可勾选）
- [ ] 客户需求全部映射到功能并完成验收。
- [ ] 项目按计划时间完成并可演示交付。
- [ ] 技术方案体现复杂度与创新性。
- [ ] 架构图、模块划分、关键设计决策已文档化。
- [ ] 用户手册可独立指导他人完成全流程操作。
- [ ] 测试计划、测试步骤、预期结果、实际结果齐全。
- [ ] 核心功能（登录、主流程、关键业务）全部可用。
- [ ] 无严重 bug、无明显性能瓶颈。
- [ ] 安全与权限控制覆盖关键接口与关键数据。
- [ ] 在目标平台可稳定运行，无额外复杂安装依赖。
