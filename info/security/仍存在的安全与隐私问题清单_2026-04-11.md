# AI-FIT 仍存在的安全与隐私问题清单（2026-04-11）

## 文档目的
本文件列出当前仍未完全解决的安全与隐私风险，按优先级给出影响与建议动作。

## P0 / 高优先级

### 1. 仓库中已跟踪开发数据库文件
- 现状：`backend/instance/aifitguard_dev.db` 已被 Git 跟踪。
- 风险：可能包含用户邮箱、哈希口令、业务记录等敏感数据；若仓库泄露，数据同步泄露。
- 建议：
  - 立即从仓库与历史提交中移除该文件。
  - 轮换受影响账号/密钥。
  - 建立“敏感文件提交拦截”（pre-commit / CI）。

### 2. 默认密钥与数据库口令仍偏弱（开发默认值）
- 现状：`SECRET_KEY` / `JWT_SECRET_KEY` / `DATABASE_URL` 仍有可预测默认值；`db_init.sql` 与 `docker-compose.yml` 存在弱口令示例。
- 风险：误用于生产或公网环境时，可导致令牌伪造、数据库被撞库。
- 建议：
  - 生产启动时强制校验：禁止弱默认值启动。
  - 提供安全随机密钥生成脚本。
  - 将示例口令改为不可直接使用的占位值。

### 3. 上传访问控制已落地，仍建议继续增强
- 现状：已实现“白名单公开目录 + 私有文件短时签名令牌”，并新增 Pose 私有视频签名下载接口。
- 剩余风险：签名链接当前可在有效期内重复使用，且缺少下载审计与异常告警。
- 建议：
  - 将私有下载令牌升级为“一次性令牌（单次消费）”。
  - 对签名下载增加访问审计（user_id、ip、资源、结果）。
  - 结合限流，避免签名链接被高频滥用。

## P1 / 中优先级

### 4. 管理员权限模型仍为单邮箱匹配
- 现状：`ADMIN_EMAIL` 字符串匹配控制管理权限。
- 风险：可维护性差、权限扩展困难，且缺少多管理员/角色能力。
- 建议：
  - 引入 RBAC（如 `is_admin` 或 `roles` 表）。
  - 管理权限与账号生命周期纳入审计。

### 5. 历史数据未完成统一重加密与脱敏迁移
- 现状：新写入数据已保护，但历史库中可能仍有明文 `storage_path` / `report_json` / `contact_email`。
- 风险：旧数据仍可直接暴露敏感信息。
- 建议：
  - 提供一次性迁移脚本，对历史字段补做清洗与加密。
  - 增加迁移校验报告与回滚方案。

### 6. 缺少接口级限流与防滥用机制
- 现状：已实现登录/找回密码/反馈提交的基础限流（IP/账号或主体维度），但仍缺更强风控能力。
- 风险：可被暴力尝试、撞库、批量刷接口。
- 建议：
  - 在生产环境引入分布式限流存储（如 Redis），避免多实例下限流不一致。
  - 对高风险接口增加验证码或风控挑战。
  - 为限流命中增加审计与告警（IP、账号、接口、频次）。

### 7. 缺少会话撤销与令牌黑名单机制
- 现状：JWT 以过期时间为主，未见主动失效/封禁机制。
- 风险：令牌泄露后在有效期内仍可访问。
- 建议：
  - 引入 refresh token + 黑名单（jti）机制。
  - 对密码修改、登出、风控事件触发主动失效。

### 8. 审计日志与告警能力不足
- 现状：缺少结构化安全审计日志（谁在何时访问了哪些敏感接口）。
- 风险：事后追溯与取证困难。
- 建议：
  - 增加统一审计日志字段（user_id、ip、ua、route、result）。
  - 配置异常行为告警（高频失败登录、异常下载等）。

## P2 / 低至中优先级

### 9. 数据生命周期策略不完整
- 现状：已具备“用户级自助删除 + 管理员清理接口/页面”的基础能力，但仍缺统一组织级策略与自动化作业。
- 风险：长期累积隐私数据，扩大泄露影响面与合规压力。
- 建议：
  - 制定按数据类型的正式保留周期（含法规/业务依据）。
  - 将清理任务纳入定时作业（cron/worker）并留存审计记录。
  - 为删除结果增加可追踪报表与失败重试机制。

### 10. 加密密钥管理需进一步工程化
- 现状：支持 `DATA_ENCRYPTION_KEY`，但密钥轮换与版本管理流程未成体系。
- 风险：长期单密钥带来运维与安全风险。
- 建议：
  - 引入密钥版本号与轮换计划。
  - 在密钥管理系统中托管（如云 KMS / 密钥服务）。

## 建议执行顺序
1. 先处理 P0：仓库数据清理、弱默认值硬阻断。
2. 再处理 P1：RBAC、历史数据迁移、限流与令牌失效机制。
3. 最后处理 P2：数据生命周期和密钥轮换工程化。

## 备注
- 本文档基于当前仓库代码状态整理。
- 随版本变更应同步更新本清单与优先级。
